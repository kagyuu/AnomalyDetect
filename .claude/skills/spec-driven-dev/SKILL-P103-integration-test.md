# 結合テスト実行

## 目的

* `docs/P008-test-direction.md` の目次にもとづき、未実施(`[ ]`または`[~]`)のテストタスクを実行する。
* 結合テストに失敗しても、この場では修正しない。記録に残すのみとする。

## インプット文書

* `docs/P008-test-direction.md` (目次 OKF形式) および各 `T000-{test-name}.md`
* `docs/P101-impl-context.md`

## アウトプット文書

* `docs/test-records/YYYYMMDD-HHMM-test-record.md`

### 動作内容

* 本フェーズは、全スプリントのP102(プログラム実装)が完了した後に、`docs/P008-test-direction.md` の全T0NNタスクをまとめて実行する。T0NNにスプリント名のラベルが付されていても、それは整理用であり、P103はスプリント単位に分割せず一括で実行する(スプリント途中でP103を差し込まない)。
* 対象テストのテストコードがまだ存在しない場合は、本フェーズが `docs/P008-test-direction/T000-{test-name}.md` の指示どおりにテストコードを新規作成してから実行する。これは、P007がテストコードを一切作成しない(P007は単体テストのみを実装対象とする)ため、結合テストコードの著者を本フェーズに明確に割り当てるものである。
  * **新規作成と書き換えは別物である**。新規作成は許可され、むしろ本フェーズの責務の一部である。禁止されるのは、既に存在するテストコードを、失敗を回避する目的で都合よく書き換えること(改ざん)である。
* クライアント・サーバ分離構成でテストハーネス(テスト実行環境)を組む場合、そのトポロジー(開発用リバースプロキシの要否、各プロセスの起動ポート、クロスオリジンの扱いなど)は、**P003が決めて `docs/ADR.md` に記録した方針に従う**(`SKILL-P003-backend-spec.md` 参照)。本フェーズで新たに判断しない。ADRに該当する記載が見つからない場合は、その旨をテスト記録に明記したうえで、必要最小限の構成で実行する(勝手に決めた構成を既定の方針であるかのように扱わない)。
* `docs/P008-test-direction/T000-{test-name}.md` に記載された手順どおりにテストを実行する。
* テストの結果(PASS/FAIL/BLOCKED/NOT RUN)を、`TEMPLATE-test-record.md` に定める記録形式で `docs/test-records/YYYYMMDD-HHMM-test-record.md` に残す。失敗の原因がアプリケーションコードではなく、テスト指示自体が上位文書(P002/P003等)と矛盾していると疑われる場合は、`TEMPLATE-test-record.md` の「テスト指示との矛盾の疑い」欄にその根拠(矛盾する上位文書の箇所)を明記する。
* FAILまたはBLOCKEDになったテストについて、その場でアプリケーションコード・テストコードを修正しない。期待値を変更して成功扱いにしない。
* テストタスクが完了したら(結果にかかわらず記録が残った時点で)、`docs/P008-test-direction.md` の該当行のチェックボックスを `[x]` に更新する。
* 全テストタスクが `[x]` になったら本フェーズを完了とする。結合テストに失敗があってもよい(そのままP104、続けてReviewer Loopに進む)。

### アウトプットを参照する文書

* `docs/P201-review-report.md` (P201、Reviewer Loopの実装横断レビュー)が、本フェーズの実行結果を確認する。
