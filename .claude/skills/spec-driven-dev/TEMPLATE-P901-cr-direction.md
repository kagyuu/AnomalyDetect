# CR-NNN

変更要求(Change Request)1件分のテンプレート。P901が、人間から会話・issue・メールなど任意の形式で示された要望をもとに `docs/P901-cr-direction/CR-NNN.md` として作成する。人間がこのファイルを自分で書く必要はない。

* 1件の要望 = 1つの CR-NNN(3桁。`CR-001` から始める)とする。複数の要望が混ざっている場合は分割し、それぞれ別ファイルにする。
* 番号は `docs/P901-cr-direction/` に既にあるファイルを見て、次の番号を採番する。
* CRは仕様そのものではない。CRにもとづいて更新されるのは `docs/P001-requirement.md` 以降の各設計書であり、このファイルは「何をなぜ変えてほしいか」の記録として残り続ける。
* **このファイルに書かないもの**: 状態(→ `docs/CR.md`)、優先度の現在値(→ `docs/CR.md`)、対処内容(→ `docs/P903-cr-records/CR-NNN.md`)。二重管理による不整合を防ぐため、これらは持たせない。
* **人間による編集**: AIが作成した後、人間が内容を修正してよい。ただし `docs/CR.md` の状態が `対応中` に移った以降は変更しない(作業の前提が動くため)。それ以降に変えたい点が出た場合は、新しいCRを起票する。

以下がテンプレート本体。

---

# CR-NNN — (タイトル)

## 起票日

YYYY-MM-DD

## 起票者

(人間の名前、または「利用者からのフィードバック」などの出所。具体的には例えば以下のような特定方法がある。判明している範囲で具体的に書く。)

* 依頼者の氏名・役職(例: 「山田太郎(業務部門責任者)」)
* 起票の元になったチケット・issueへのリンク(例: 「Jira: PROJ-123」「GitHub Issue #45」)
* 打ち合わせ・レビューの議事録への参照(例: 「2026-08-03 定例会議事録 3節」)
* 問い合わせ窓口・サポートチケットの参照番号
* **`docs/P900-change-concept.md`(P900のファイル方式)から起票した場合は、次の固定書式で書く。**

  ```
  docs/P900-cr-concept/P900-change-concept_{YYYYMMDD}_{HHMMSS}.md 項目{N}「{項目の見出し}」
  ```

  例: `docs/P900-cr-concept/P900-change-concept_20260826_143000.md 項目3「予約一覧に絞り込みを付けたい」`

  項目番号だけでなく**見出し文字列も併記する**(人間が項目を挿入・削除すると番号がずれるため)。この書式を固定することで、後から機械的に検索して出所を辿れる。P901が再実行された際の重複起票の判定にも、この記述を使う。
* 上記が特定できない場合は「利用者からのフィードバック(詳細不明)」のように、不明である旨を明記する(出所不明のまま書かない)

## 背景・課題

* なぜこの変更が必要か。現状どのような困りごとがあるか。

## 変更要求の内容

* 何をどう変えてほしいか。画面・API・データモデル・非機能要件のうち、どこに関わる変更かを具体的に書く。
* 対応する既存の仕様箇所があれば、`docs/P00N-*.md` の該当箇所を明記する。

## 期待する振る舞い

* 変更後、どのような入力に対してどのような結果になっていればよいか(受け入れ条件)。
* P904がこの節を1項目ずつ確認するため、1項目=1行の箇条書きにして、確認可能な粒度で書く。

## 影響が想定される範囲

P901時点での見積もりであり、確定した対応範囲ではない(確定は P903 が `docs/P903-cr-records/CR-NNN.md` に記録する)。

* 画面: ...
* API: ...
* データモデル: ...
* 関連ADR: (あれば ADR-NNN を記載)
* 既存ADRに抵触する要望(既に採用済みの決定を覆す要望)であれば、その旨とどのADRかを明記する。

## 優先度の判断理由

* 影響度×緊急度ルーブリック(`SKILL-P901-cr-create.md` 参照)を適用した結果と、そう判断した理由。
* 機械的に表へ当てはめるだけでは判断がつかない場合は、妥当と考える優先度を選んだうえで理由を書き、その行(または直後の行)に "★FIXME★" を付ける。
* 優先度の現在値そのものは `docs/CR.md` が持つ(運用の中で人間が変更しうるため)。ここに残すのは判断の理由である。
