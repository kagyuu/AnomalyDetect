# システム要件定義

## 目的

* 漠然としたアイデアを、後続フェーズが詳細化できる具体的なシステム概要に落とし込む。

## インプット文書

* `docs/P000-concept-analysis.md` (P000でファイル方式を選んだ場合。人間が記入した要求・要望の原文)
* 上記が存在しない場合は、人間との対話 (システム設計者の中にある漠然としたアイデア)

## アウトプット文書

* `docs/P001-requirement.md`
* `docs/.mode` (実行モード。本フェーズの完了時に人間が選んだ値を書き出す)

### アウトプットの記載内容

* アプリケーションの概要(何のためのアプリか、誰が使うか、どんな課題を解決するか)
* システムの前提(想定ユーザー数・規模、デプロイ先、認証要否、連携・参考にする既存システムの有無など)
* フロントエンドで使う技術(例: React / Angular / Vue)とその選定理由
* バックエンドで使う技術(例: FastAPI / Next.js / Java EE)とその選定理由
* 画面一覧(アプリが持つ全画面)
* 画面遷移図(画面間の遷移関係。どの操作でどの画面に移動するか)
* 各画面の入出力項目(画面ごとの入力項目・表示項目)
* 入出力に紐づくバックエンドAPI(各画面の入出力がどのAPIを呼ぶか)
* バックエンドAPI一覧(メソッド・パス・用途を一行で)
* 非機能要件(性能・可用性・セキュリティ・スケーラビリティ・想定同時利用者数・ログ出力先とその監視方法など、決められる範囲で)
* テスト方針(方針レベルのみ。詳細なテスト計画はP006)

### アウトプットを参照する文書

アウトプットの記載内容は、次の文書を作成できる程度に具体的であること

* `docs/P002-frontend-spec.md`
* `docs/P003-backend-spec.md`
* `docs/P004-traceability-matrix.md`
* `docs/P005-impl-plan.md`
* `docs/P006-test-plan.md`
* `docs/P009-acceptance-direction.md`

## 動作

### 1. 要求の具体化

* `docs/P000-concept-analysis.md` が存在する場合は、それを起点に `docs/P001-requirement.md` を組み立てる。
  * 人間が記入した内容を勝手に狭めたり広げたりしない。**書かれていないことは「書かれていない」として扱う。**
  * 任意章が空欄、または「わからない」「おまかせ」と書かれている箇所は、Agent自身の想定で補い、補った記述に隣接して★FIXME★を付ける(共通指示の既定どおり)。
  * GUIテンプレートの「前提を満たさないとき」列、CLIテンプレートの「終了コードと異常系」表に**空欄がある場合、それは異常系が未定義であることを意味する**。想定で補ったうえで★FIXME★を付け、人間が後から確認できるようにする。空欄を「異常系は不要」と読み替えてはならない。
  * 誤字と思われる箇所は、勝手に直さず人間に確認する(誤字だと思ったものが固有名詞であることがある)。
* 存在しない場合は、従来どおり対話で具体化する。本フェーズは「作業主体: 人間+AI」であり、漠然としたアイデアを具体化する対話を行ってよい。

### 2. 入力完了の確認 (V1.2で追加)

`docs/P001-requirement.md` の草案を作成したのち、**人間に確認を求め、明示の合図があるまでP002へ進まない。**

* 確認する内容は次の2つ。**1回の問い合わせにまとめて提示する**(人間から見れば「要求は出し終えた。ここからこう進めてくれ」という1つの意思決定であるため)。
  1. **要求の入力は以上でよいか。** 併せて、★FIXME★を付けた箇所(想定で補った箇所)の一覧を提示する。
  2. **この先の進め方(実行モード)をどちらにするか。** `SKILL.md` の「実行モード」を参照し、次の2つを提示する。
     * `一気通貫` — P302まで人間のゲートなしで走り切る。不足はAgentの想定で補い★FIXME★を付け、納品後にCRで直していく。**(既定)**
     * `工程確認` — Stepの境界(最大6箇所)で止まり、溜まった★FIXME★を人間が解消してから次へ進む。
* 人間が選んだ値を `docs/.mode` に1語だけ書き出す(`一気通貫` または `工程確認`)。
* **選択が得られない場合(非対話実行など)は `一気通貫` とする。** 勝手に `工程確認` を選ばない。

> **この確認は、V0.4が撤廃した「フェーズごとの人間レビュー」の復活ではない。**
> P001は本SKILLで唯一「作業主体: 人間 + AI」と規定された対話フェーズであり、ここで行っているのは**その対話をいつ終えるかの判断を人間に委ねること**である。P002以降は、モードが `一気通貫` である限り一切の人間ゲートを持たない。
> この区別は重要である。V0.5は、実行担当Agent向けのテンプレート3件から「停止して次の指示を待て」という記述を不具合として削除した。本節はそれとは別物であり、**同種の記述として削除してはならない。**

### 3. 完了

* `docs/.inprogress` を `P002` に更新する。
