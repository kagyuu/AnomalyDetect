# テスト計画

## 目的

* テスト計画を作成して、フロントエンドおよびバックエンドをどのような単位でどのような観点でテストするかを確定する。

## インプット文書

* `docs/P001-requirement.md`
* `docs/P002-frontend-spec.md`
* `docs/P003-backend-spec.md`
* `docs/P005-impl-plan.md`

## アウトプット文書

* `docs/P006-test-plan.md`

### アウトプットの記載内容

* 各テストの目的・観点。
  * V字モデルに沿って、以下の4つのテストレベルに分けて目的を明確化する

| テストレベル | 目的 |
| --- | --- |
| 単体テスト | ユーザインタフェース設計書、システム詳細設計で定義した、画面、APIが、単体で仕様どおりに動くか |
| 結合テスト | ユーザインタフェース設計書、システム詳細設計で定義した、画面、APIが、連携して仕様通りか |
| システムテスト(総合テスト) | システム要件定義書の要件・非機能要件を満たしているか |
| 受け入れテスト | 発注者・利用者・運用者の視点で、本番相当環境で問題なく使えるか |

  * テストの観点を明確化して、どのテストレベルで行うかを明確化する
    * 機能観点: ユーザインタフェース設計書、システム詳細設計の各APIエンドポイント・各画面ごとの具体的なテストケース(正常系 + 主要な異常系: バリデーションエラー、Not Found、認可エラーなど)
    * 非機能観点: 性能・負荷・セキュリティ・運用(ログ監視)など
    * 運用観点(再起動耐性): データストアを持つ場合は、**アプリケーションを停止・再起動しても正常に起動すること**を確認する観点を必ず含める。`docs/P003-backend-spec.md` に記載されたマイグレーション方式が冪等でない場合、2回目以降の起動で失敗する。この観点は、テストごとに新しい一時データストアを作る単体テスト・結合テストでは検出できない(常に初回実行になるため)ため、独立した観点として明示すること。
  * 単体テスト・スプリント内結合テストは `docs/P007-impl-direction.md`/`docs/P008-test-direction.md` で、スプリント横断・システム・受け入れテストは `docs/P009-acceptance-direction.md` で、それぞれこの計画をもとに実装指示を別途作成する旨を前提とする。
* そのほか、外部APIのモック方針、テストデータの準備方法など、テスト遂行上の技術的な決め事を記載する
* **テストデータのライフサイクル方針を明記する**。永続化されたデータストア(DB・ファイル等)を共有して実行するテストは、実行のたびにデータが累積し、**2回目以降の実行だけが失敗する**状態になりやすい(例: 一覧画面の要素が前回実行分と重複して一意に特定できなくなる、件数を検証するテストが増えた分だけ失敗する)。これを防ぐため、次の2点をこのフェーズで決めて記載する。
  * **ベースラインへ復元する単位**(テスト1件ごと / テストスイートの実行ごと / まったく復元しない)。**既定はテストスイートの実行ごと**とする。テスト1件ごとの復元は、先行するテストが用意したデータまで消すため、テスト間にデータの依存関係がある場合はかえって壊れる。
  * **「ベースライン」が何を指すか**。単なる全行削除ではなく、**マイグレーション(および初期データ投入)を適用した直後の状態**を指すのが通常である。基準となるユーザーやマスタデータがマイグレーションで投入される場合、全行削除するとログインすらできなくなる。
  * ここで求めているのは、テストが**スイート単位で再実行可能である**こと(何度実行しても同じ結果になること)であり、個々のテストが単独で実行可能であることではない。テスト間のデータ依存を許容するかどうかは、この方針の中で決めて記載する。
  * この方針は `docs/P008-test-direction.md`・`docs/P009-acceptance-direction.md` が各テストの「事前準備」に具体化する。
* なお、ここで作るのは、テストとして何を行うかの「テスト計画」であり、個々のテストケースの実装や具体的なパラメータは P007・P008・P009 で、この文書をもとに実装指示を別途作成する。

### アウトプットを参照する文書

アウトプットの記載内容は、次の文書を作成できる程度に具体的であること

* `docs/P007-impl-direction.md` (目次 OKF形式)
* `docs/P007-impl-direction/U000-{sprint-name}.md` (各スプリントの実装指示、000はスプリント番号(実行順))
* `docs/P008-test-direction.md` (目次 OKF形式)
* `docs/P008-test-direction/T000-{test-name}.md` (000はテスト番号(実行順)、test-name はテスト名)
* `docs/P009-acceptance-direction.md` (目次 OKF形式)
* `docs/P009-acceptance-direction/A000-{test-name}.md` (000はテスト番号(実行順)、test-name はテスト名)
