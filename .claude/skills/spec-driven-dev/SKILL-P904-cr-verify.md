# 変更要求の反映確認

## 目的

* P903で行った修正が、`docs/P901-cr-direction/CR-NNN.md` に記載された変更要求の内容をすべて満たしているかを確認する。
* 確認結果を `docs/P903-cr-records/CR-NNN.md` の「反映確認(P904が記載)」の節に書き、`docs/CR.md`(状態の台帳)の状態列を更新する。

## インプット文書

* `docs/P901-cr-direction/CR-NNN.md` (変更要求。特に「期待する振る舞い」)
* `docs/P903-cr-records/CR-NNN.md` (P903が記録したスコープ決定と対処内容)
* `docs/CR.md` (状態の台帳)
* P903で更新された `docs/P002-frontend-spec.md` 〜 `docs/P302-deliver.md`、ソースコード、テスト記録
* `docs/P008-test-direction/` / `docs/P009-acceptance-direction/` (確認に用いるテストIDの特定のため)

## アウトプット文書

* `docs/P903-cr-records/CR-NNN.md` (「反映確認(P904が記載)」の節への追記)
* `docs/CR.md` (対象CRの状態列の更新)

### アウトプットの記載内容

* 本フェーズを開始したら、まず `docs/CR.md` の対象CRの状態列を `反映確認中` に更新する。
* `docs/P901-cr-direction/CR-NNN.md` の「期待する振る舞い」を**1項目ずつ**取り上げ、それがテスト(P008の結合テスト/P009の受け入れ結合テスト)で確認できているかを検証する。項目とテストID・確認方法・結果の対応表を、記録ファイルの「『期待する振る舞い』の確認結果」に記載する。
  * テストで確認できない項目(設計書の記述のみで完結する変更など)は、代わりにどの文書のどの記述で確認したかを「確認方法」に書く。「確認した」とだけ書かない。
* あわせて、記録ファイルの「スコープ決定」の節を参照し、対象外としたフェーズの判断が妥当だったか(実際には再オープンが必要だった箇所が残っていないか)を確認する。
* すべての項目を確認できた場合は、記録ファイルの「反映確認の結論」にその旨を書き、`docs/CR.md` の状態列を `完了` に更新する。**完了した行は削除しない**(台帳は完了したCRも状態列を更新して残し続ける)。
* 確認できない項目がある場合は、状態列を `対応中` に戻し、「反映確認の結論」に不足している対応を具体的に明記したうえで人間に報告する。

### アウトプットを参照する文書

* `docs/P905-*` (ADR更新確認) が、同じ記録ファイルにADR判定結果を追記する。
