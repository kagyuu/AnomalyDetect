# 設計書修正

## 目的

* `docs/P011-impact-analysis.md` で分析した内容にもとづき、該当する設計書(`docs/P002-frontend-spec.md` 〜 `docs/P009-acceptance-direction.md` のうち関係する文書)を修正する。
* 修正後、再度P010(設計書横断レビュー)を実行し、矛盾が解消されたかを確認する。

## インプット文書

* `docs/P011-impact-analysis.md`
* 修正対象となる `docs/P002-frontend-spec.md` 〜 `docs/P009-acceptance-direction.md`

## アウトプット文書

* 修正された `docs/P002-frontend-spec.md` 〜 `docs/P009-acceptance-direction.md` (該当する文書のみ)
* 専用の新規ドキュメントは作らない。どの文書のどこを、`docs/P011-impact-analysis.md` のどの矛盾点にもとづいて修正したかは、修正した文書自体に追記する(例: 該当箇所に「※P011矛盾点#1にもとづき修正」等の注記を残す)。

### 動作内容

* `docs/P011-impact-analysis.md` に列挙された矛盾点を、優先度の高いものから順に修正する。
* 1つの文書に対する修正は、その文書のフェーズが本来担うべき役割(例: P002は外部契約、P003は内部実現)の範囲を超えない。役割を超える修正が必要と分かった場合は、その旨を明記したうえで該当フェーズの文書を修正する。
* P004(トレーサビリティマトリクス)・P007〜P009(実装/テスト指示の目次・タスク)に波及する修正がある場合は、それらも合わせて更新する。
* 修正が既存のADR(`docs/ADR.md`)に関わる場合(すでに採用済みの決定を覆す場合)は、この時点でADRを新規追記せず、後続のP021(ADR整理)で反映する旨を `docs/P011-impact-analysis.md` またはP010の再実行結果に申し送る。
* 修正が完了したら、P010(設計書横断レビュー)を再実行する。

## 動作

* 共通指示以外は特になし
* Plan Loop Stepの停止条件(P010を3回実行してもなお矛盾が残る)に該当した場合は、これ以上修正を試みず処理を停止して人間に報告する。
