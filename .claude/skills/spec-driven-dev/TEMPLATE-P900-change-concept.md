# P900 変更要望の整理

変更してほしいことを人間が書くためのひな型。P900が本ファイルを複製して `docs/P900-change-concept.md` を作成し、**人間が記入する**。P901がこれを読んでCR(変更要求書)に起票する。

* `<!-- 記入してください: … -->` が未記入箇所の目印。記入したらコメントごと消す。
* **必須**の章が1つでも未記入だと、P901へ進めない。**任意**の章は空欄のままでよい。

## 書き方の注意

* **1項目には1つの変更だけ書く。** 「AとBとCを直してほしい」は3項目に分ける。**1項目 = 1つのCR**になるため、混ぜて書くと対応の可否や優先度を項目ごとに判断できなくなる。
* **「現状」と「変更後」の両方を必ず書く。** 「〜してほしい」だけでは、変更前後の差分が定義できない。差分が定義できないと、P904が「変更が実際に反映されたか」を確認するときに、何を確認すればよいかが決まらない。
* **「現状」に書くことが無い場合**(そういう機能自体が無い場合)は、「無い」とだけ書かず、**どこに無いのか**を書く。例:「予約一覧画面に絞り込みの入力欄が無い(検索条件はどこにも指定できない)」。場所が分かれば、どこに足せばよいかが決まる。
* **優先度がわからなければ空欄でよい。** P901が影響度×緊急度のルーブリックで仮置きし、★FIXME★を付けて確認を求める。
* 対応できない要望・見送りになる要望もある。その場合もCRとして記録が残り、却下の理由が書かれる(黙って消えることはない)。
