# ADR更新確認

## 目的

* 今回のRefactorで行った変更要求(CR)対応が、既存のADR(`docs/ADR.md`)を覆す、または新たな技術的決定を含んでいないかを確認し、必要であればP021(ADR整理)と同じ手順でADRを更新する。

## インプット文書

* `docs/P903-cr-records/CR-NNN.md` (今回完了したCRの対処記録)
* `docs/P901-cr-direction/CR-NNN.md` (今回完了したCRの変更要求)
* `docs/ADR.md` / `docs/ADR_master.md`
* P903で変更されたソースコード・設計書

## アウトプット文書

* `docs/P903-cr-records/CR-NNN.md` の「ADR更新確認(P905が記載)」の節(更新の要否にかかわらず必ず記載する)
* `docs/ADR.md` (更新が必要な場合)
* `docs/ADR_master.md` (既存ADRを廃止する場合)

### アウトプットの記載内容

* 今回のCR対応で、新たな技術的決定(新しいライブラリ導入、認証方式の変更など)を行った場合は、`SKILL-P021-adr.md` と同じ手順で新規ADRを追記する。
* 既存のADRの前提を覆した場合は、そのADRを「廃止」にして `docs/ADR_master.md` に移し、廃止理由(どのCRにより、どのADRに置き換わったか)を明記する。
* 更新の必要がない場合(実務上はこちらの方が多い)も、その旨を明記する。ADR自体を更新しない場合でも、「更新不要と判断した」という判定結果は必ず記録する。記録先は `docs/P903-cr-records/CR-NNN.md` の「ADR更新確認(P905が記載)」の節に固定する(P903が作成し、P904が追記済みのファイルが既に存在する)。そこに1行程度で「ADR更新: 不要(理由: ...)」のように追記することを、本フェーズの成果物とする(本SKILLの規約。詳細は `SKILL.md` の「各フェーズで作成するドキュメント」表のP905行を参照)。この記録の有無は、`SKILL.md`「ステップ0」がRefactorの完了を判定する手掛かりでもあるため、省略しない。

### アウトプットを参照する文書

* 以降のPlan Loop Step(P002・P003など)が、既存の決定を確認する際に参照する。

## 動作

* 共通指示以外は特になし
* 本フェーズが完了したら、Refactor(P901〜P905)は完了とする。`docs/CR.md` に状態が `未対応` のCRが残っていれば、そのCRについてP902に進んで次のCRの処理に入ってよい(要求は既に `docs/P901-cr-direction/` にあるため、P901の再実行は不要)。人間から新しい要望が示された場合はP901から始める。
