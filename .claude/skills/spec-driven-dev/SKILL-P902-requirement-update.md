# 要件定義更新

## 目的

* `docs/CR.md`(状態の台帳)で状態が `未対応`(または `対応中` で優先度の高いもの)のCRを選び、その変更要求 `docs/P901-cr-direction/CR-NNN.md` にもとづいて `docs/P001-requirement.md` を更新する。
* 更新前の原本は破棄せず、`docs/P001-requirement-old/P001-requirement_{YYYYMMDD}_{CR番号}.md` へ退避して保持する。
* **`docs/` 直下に置く要件定義は、常に現在有効な `docs/P001-requirement.md` の1本だけとする。** 無効になった原本を直下に並べると、どちらが有効かがファイル名から判別できず、CRを重ねるたびに同じ接頭辞のファイルが増えていく。これは `SKILL-P021-adr.md` が「廃止された決定は `docs/ADR_master.md` に退避し、`docs/ADR.md` には現在有効な決定のみを残す」としているのと同じ原則である。

## インプット文書

* `docs/CR.md` (どのCRを対象にするかを、状態列・優先度列から選ぶため)
* `docs/P901-cr-direction/CR-NNN.md` (対象CRの変更要求。要求の本文はこちらにあり、`docs/CR.md` には無い)
* 更新前の `docs/P001-requirement.md`

## アウトプット文書

* `docs/P001-requirement.md` (更新後)
* `docs/P001-requirement-old/P001-requirement_{YYYYMMDD}_{CR番号}.md` (更新前の原本)

### アウトプットの記載内容

* **着手時に、旧形式の退避ファイルを移行する**(V1.2で追加)。`docs/` 直下に `docs/P001-requirement_*.md` にマッチするファイルがあれば、`docs/P001-requirement-old/` へ移動し、下記の注記を付す。
  * パターンには**アンダースコアを必ず含める**。`docs/P001-requirement.md`(アンダースコアが無い本体)を誤って退避しないための歯止めである。
  * この移行は安全である。移動するのは既に無効と確定した過去のバックアップだけであり、現在有効な本体には触れない。移行後に再実行しても、直下に対象が無いため何も起きない(冪等)。
  * V1.1以前に開始されたプロジェクトを引き継いだ場合にのみ該当する。該当が無ければ何もしない。
* **本フェーズは冪等に実行する**(P902完了直後にセッションが切れて再度P902から再開しても、原本を失わないため)。上記の移行のあと、以下の順で確認する。
  1. `docs/P001-requirement-old/P001-requirement_{YYYYMMDD}_{CR番号}.md`(バックアップ先)が既に存在するか確認する。存在する場合、既に本フェーズが実行済みである可能性が高いため、**バックアップのコピーは行わない**(上書きしない)。
  2. `docs/P001-requirement.md` 本体に、対象CRの変更箇所を示す注記(下記の「※CR-NNNにより追加」等)が既に含まれているか確認する。含まれている場合、本フェーズは完了済みとみなし、そのままP903に進む(再度の更新は行わない)。
  3. バックアップ先が存在せず、かつ本体にも対象CRの注記が無い場合にのみ、通常どおり更新前の `docs/P001-requirement.md` を `docs/P001-requirement-old/P001-requirement_{YYYYMMDD}_{CR番号}.md` にコピーしてから、`docs/P001-requirement.md` 本体を更新する。ディレクトリが無ければ先に作成する。`{CR番号}` は今回対応するCRのID(例: `CR-001`)を使う。日付だけでは同じ日に複数件のCRを処理した場合にバックアップファイルが衝突する(2件目の処理で1件目のバックアップを上書きしてしまう)ため、CR番号を必ずファイル名に含める。
  4. バックアップ先は存在するが本体に対象CRの注記が無い(半端な状態)場合は、バックアップを上書きせずに本体の更新のみを行う。
* **退避したファイルの冒頭に、次の固定書式で注記を入れる。**

  ```
  > **この文書は無効です。** CR-NNN 対応前の原本(YYYY-MM-DD時点)です。
  > 現在有効なシステム要件定義は `docs/P001-requirement.md` です。
  ```

  ディレクトリ名だけでは足りない理由は、**IDEのタブや検索結果にはディレクトリ名ではなくファイル名しか出ない**ためである。ファイルを開いた瞬間に、これが有効な文書でないと分かる必要がある。本文は改変せず、この注記を先頭に足すだけにとどめる。
* 更新は、`docs/P901-cr-direction/CR-NNN.md` に書かれた内容にもとづく範囲にとどめる。CRと無関係な既存記述は変更しない。
* どのCR-NNNにもとづく変更かを、変更箇所に注記する(例: 「※CR-001により追加」)。この注記は、上記の冪等性判定にも使われるため省略しない。
* 状態列(`docs/CR.md`)の `対応中` への更新は、P903が着手時に行う。本フェーズでは状態を変更しない。
