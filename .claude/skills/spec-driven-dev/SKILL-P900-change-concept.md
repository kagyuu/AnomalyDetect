# 変更要望の整理

## 目的

* 人間の変更要望を、P901が読める形に整理する。
* 変更要望をプロンプトだけで伝えると、**「どうしてほしいか」は書かれるが「現状どうなっているか」が抜け落ちる**。現状が書かれていないと変更前後の差分が定義できず、P904が「期待する振る舞い」をテストIDと突き合わせて確認する際に、何を確認すればよいかが決まらない。
* **本フェーズは「人間に書いてもらうための枠を用意する」フェーズであり、内容を代筆するフェーズではない。** 不足の補完はP901の責務である。

## インプット文書

* 人間からの変更要望 (漠然としたもので構わない)
* `TEMPLATE-P900-change-concept.md` (ひな型の元)

## アウトプット文書

* `docs/P900-change-concept.md` (ファイル方式を選んだ場合のみ。**本文を書くのは人間**)

### アウトプットの記載内容

* ひな型は `TEMPLATE-P900-change-concept.md` をそのまま複製する。内容を先回りして埋めない。
* テンプレート内の未記入箇所は `<!-- 記入してください: … -->` 形式のHTMLコメントで示される。P000と同じ記法であり、★FIXME★・★ACCEPTED★とは別物である。
* **複数の変更要望を1つのファイルに書ける。** 1項目 = 1つの変更したいこと = 1つのCRとなる。

### アウトプットを参照する文書

* `docs/P901-cr-direction/CR-NNN.md` (P901が本ファイルの各項目からCRを起票する)

## 動作

### 1. `docs/P900-change-concept.md` の有無を確認する

### 2. 存在しない場合 — 人間に2択を提示する

次の2つを提示し、人間に選ばせる。**勝手にどちらかを選んで先へ進まない。**

* **(a) 変更要望をファイルの形で整理する**
  * `TEMPLATE-P900-change-concept.md` を複製して `docs/P900-change-concept.md` を作成する。
  * **ここで処理を終える。P901以降へ進まない。**
  * `docs/.inprogress` は `P900` のままにする。
  * 人間には、ひな型を作成したこと・記入後に再度実行すればP901から続きが始まること・複数の要望を項目として並べられること・**各項目に「現状」と「変更後」の両方を書く必要があること**を伝える。
  * **これは異常事象ではないため、`docs/.stop-report.md` は書かない**(理由は `SKILL-P000-concept-analysis.md` と同じ)。
* **(b) 従来どおりプロンプトで伝える**
  * `docs/P900-change-concept.md` は作成しない。
  * そのままP901へ進む(`docs/.inprogress` を `P901` に更新する)。**これが既定の方式である。**

### 3. 存在する場合 — プレースホルダの残存を確認する

`docs/P900-change-concept.md` の中に `<!-- 記入してください:` が残っていないかを確認する。ファイルが存在することをもって「記入済み」と判断してはならない。

**判定の単位は章・項目であり、表のセル1つではない**(`SKILL-P000-concept-analysis.md` と同じ規定)。

* **必須の章・項目が丸ごと未記入**の場合 — 残っている箇所を項目単位で列挙して人間に報告し、処理を終える(`docs/.inprogress` は `P900` のまま)。`docs/.stop-report.md` は書かない。
* **表のセル単位でプレースホルダが残っている場合** — 停止しない。P901へ進む。**ただし「現状」欄だけは例外**で、これが空のまま起票させてはならない(下記)。
* **任意章にのみ残っている、または何も残っていない場合** — P901へ進む(`docs/.inprogress` を `P901` に更新する)。

**「現状」欄をセル単位の例外とする理由**: 他のセルは、空欄であればP901が質問して補える。しかし「現状」は**人間が実際に見ている事実**であり、AgentもP901も推測で埋めてはならない(推測で埋めると、人間が困っている実際の事象とずれたまま対応が進む)。「現状」が空の項目は、セル単位であってもP901が不足として数え、質問して補完する(`SKILL-P901-cr-create.md` 参照)。

### 禁止事項

* **`docs/P900-change-concept.md` の空欄を、Agent自身の想定で埋めない。** とくに「現状」欄を推測で埋めてはならない。現状は実際に人間が見ている事実であり、Agentが実装から推測して書くと、人間が困っている実際の事象とずれる。
* 人間が記入した内容を書き換えない。本ファイルは人間が書いた原文としてそのまま `docs/P900-cr-concept/` へ退避され、以後の監査対象になる。
* 本フェーズでCRを起票しない。起票はP901の仕事である。

### 補足

* 本フェーズは、変更要望をファイルで受け取る手段を**任意で提供する**ものである。会話・issue・メールなど任意の形式で伝える従来の方式が既定であり、それを廃止するものではない。
* `docs/P900-change-concept.md` は、全項目のCR起票が完了した時点でP901が `docs/P900-cr-concept/P900-change-concept_{YYYYMMDD}_{HHMMSS}.md` へ退避する。したがって、次に本フェーズが実行されるときには再びファイルが存在しない状態から始まる。
