# 実装構造生成/修正

## 目的

* コードベースが既にある場合は、その目次となる `{ソースツリー}/INDEX.md` を作る。無ければ、見出しと「(実装前)」の注記だけを持つ最小限のプレースホルダファイルを作る(空ファイルではない。後述「アウトプットの記載内容」参照)。
* 目的は、後続のExecutor・Reviewer LoopがソースコードをすべてReadし直さなくても、ディレクトリ構成と主要ファイルの役割を把握できるようにすることである。

## インプット文書

* 既存のソースツリー(`app/` または `client/` `server/` など、`docs/P007-impl-direction/U000-{sprint-name}.md` で定めたコード格納先)。実装着手前はこのディレクトリ自体がまだ存在しないことが普通にあるため、その場合は無いことを前提として扱う(後述「アウトプットの記載内容」参照)。

## アウトプット文書

* `{ソースツリー}/INDEX.md` (ソースツリーごとに1つ。例: `client/INDEX.md` `server/INDEX.md`、単一アプリなら `app/INDEX.md`)

### アウトプットの記載内容

* INDEX形式(`SKILL.md` の「INDEX形式について」参照)にもとづき、そのソースツリー配下の主要ディレクトリ・主要ファイルを一覧し、各項目に一言概要を添える。
* 記載例:

```markdown
# server/ INDEX

- app/main.py — FastAPIアプリのエントリポイント
- app/routers/ — APIハンドラ層
  - reservations.py — 予約関連API
  - rooms.py — 会議室関連API
- app/repositories/ — データアクセス層
- app/schemas.py — Pydanticスキーマ定義
- tests/ — Unit Test / 結合テスト
```

* コードベースがまだ存在しない場合(P001完了直後など)は、`{ソースツリー}/INDEX.md` を、見出しと「(実装前)」の注記のみを持つ最小限のプレースホルダファイルとして作成する。これは「空ファイル」ではなく、この見出し+注記という具体的な内容を持つファイルである。
  * このとき `client/` `server/`(または単一アプリの場合の `app/`)などソースツリーのディレクトリ自体がまだ存在しない場合は、`INDEX.md` を書き込む前に、まず本フェーズがそのディレクトリ自体を作成する。
* **初期化済みだが未実装の場合**(人間が本Skillを使い始める前にビルドツールでスキャフォールドしていた場合など。`uv init`/`npm init` 等は済んでいるが、実装コードは0行)は、「コードベースが既にある」と「無い」のどちらの分岐にも単純には当てはまらない。この場合は、実在するファイル(`pyproject.toml`/`package.json` 等の初期化ファイル)を一覧に含めつつ、「(実装前)」の注記も残すハイブリッド形式で作成する(初期化済みファイルの情報を捨てず、かつ未実装であることも明示する)。
  * 本Skillが要件定義から通しで実行された場合、コード格納先の初期化はExecutor(P102)が行うため、本フェーズの実行時点ではまだ初期化されていないのが通常である(`SKILL-P007-impl-direction.md`・`SKILL-P102-implement.md` 参照)。したがってこの分岐に該当するのは、上記のように人間が事前に初期化していた場合などに限られる。
* 既に `INDEX.md` がある場合は、現在のソースツリーの実態と差分がないかを確認し、差分があれば更新する。実装されていないのに記載されている項目、実装されているのに記載がない項目の両方を確認する。
