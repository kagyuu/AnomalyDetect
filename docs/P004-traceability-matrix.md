## 4. DEVIATED (環境制約による意図的な代替)

**該当なし(0 件)。**

> **本節の経緯**: 本フェーズの初稿では NFR-006(Linux / Windows 両対応)を `DEVIATED` と判定していた。「検証可能な Linux 環境が無く、Windows でしか確認できない」という前提に立っていたためである。**この前提は誤りであった。** 実際に確認したところ、本プロジェクトの実行環境には WSL2 上の Ubuntu が存在し、Linux 実機での検証が可能である。
>
> | 検証環境 | OS | Python | DuckDB |
> | --- | --- | --- | --- |
> | Windows | Windows 11 Pro (10.0.26200) | 3.14.2 | 1.5.5 |
> | Linux | Ubuntu (WSL2, kernel 5.15.153.1) x86_64 | 3.10.12 | 1.5.5 |
>
> したがって NFR-006 は `DEVIATED` ではなく `OK` である(2章の表を訂正済み)。両 OS での実行確認は **P009(受け入れ結合テスト)が担当する**。
>
> **この訂正から導かれる設計上の制約**: 検証環境の Python が Windows 側 3.14、Linux 側 3.10 と異なるため、**コードが動作すべき Python の下限を 3.9 とし、3.10 以降でのみ使える構文・標準ライブラリを使わない**。具体的には、実行時に評価される `X | None` 形式の型注釈(`typing.Optional` を使う)、`match` 文、`tomllib` を使わない。この制約を P001 3.1 および P003 に反映する。★ACCEPTED★ 検討: 検証環境に合わせて下限を 3.10 とする案。**不採用**。配布先の閉域環境の Python 版が未確認であり(P001 3.1 の ★FIXME★)、企業内の Linux では 3.6〜3.9 が使われていることが珍しくないため、下限を下げておくほうが安全である。残存リスク: 3.9 では使えない新しい構文の恩恵(構造的パターンマッチなど)を受けられないが、本アプリの規模では実害がない。
