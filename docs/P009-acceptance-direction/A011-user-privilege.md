# 【テストID】A011 — 一般ユーザー権限での実行

## 【目的】

* `docs/P001-requirement.md` NFR-004「一般ユーザーで実行可能であること。管理者権限を要求しない」を確認する。
* 運用者が日常的に手で実行するツールであり(P000 第1章「誰が使うか: アプリケーションの運用者」)、実行のたびに管理者権限を要求する設計は受け入れられない。
* あわせて、**書き込む先がカレントディレクトリと `temp_directory` に限られている**こと(NFR-008 の一部)を確認する。

## 【対象モジュール】

* 全モジュール(特に `reporter.py`(書き込み先)、`bootstrap.py`(`temp_directory`)、`loaders`(読み取りのみ))

## 【前提条件】

* `docs/P009-acceptance-direction.md` 4.1 のビルド確認が成功していること。**失敗した場合は `BLOCKED`。**
* A001 が PASS していること。

## 【使用するテストデータ】

* `app/tests/_work/normal/logs/`(読み取り専用)

## 【事前準備】

1. スイート初期化がこのスイートの実行で 1 回だけ済んでいること。
2. `tempfile.TemporaryDirectory` で作業ディレクトリを作る。
3. **管理者権限で実行していないことを確認する。**
   * Windows: `ctypes.windll.shell32.IsUserAnAdmin()` が 0 であること。
   * Linux: `os.geteuid() != 0` であること。
   * **管理者/root で実行している場合、本テストの結果は無意味であるため `NOT RUN` として記録し、その旨を明記する。**
4. **入力ディレクトリを読み取り専用にする**(書き込みを試みていないことの確認)。
   * 一時ディレクトリへ入力データをコピーし、**配下のファイルに読み取り専用属性を付与する**(Windows / Linux とも `os.chmod(path, 0o444)`)。
   * **確認の主たる手段は、実行前後のファイル一覧(パス・サイズ・更新日時)の比較とする。** ★ACCEPTED★ 検討: ディレクトリ自体を読み取り専用にして書き込みを OS に禁止させる案。**不採用**。**Windows のディレクトリに対する読み取り専用属性は配下のファイル作成を防がない**ため、「書き込もうとしたが失敗した」のか「そもそも書き込んでいない」のかを区別できない。ACL による拒否は実行環境によっては設定できない。ファイル一覧の実行前後比較は、確認したい内容(**アプリが入力ディレクトリへ書き込まないこと**)をより直接的に確認できる。残存リスク: アプリが書き込んだ直後に元の内容・更新日時へ復元した場合は検出できないが、そのような実装は存在しない(`loaders` はいずれも読み取りモードでのみ開く)。

## 【実行手順】

1. 実行前に、入力ディレクトリと作業ディレクトリのファイル一覧(パスと更新日時)を記録する。
2. サブプロセス起動する。
3. 終了コードと標準エラーを取得する。
4. 実行後に、入力ディレクトリと作業ディレクトリのファイル一覧を再度取得する。
5. 差分を確認する。
6. `app/` 配下(ソースツリー)のファイル一覧も、実行前後で比較する。

## 【実行コマンド】

```
python -m unittest discover -s app/tests/acceptance -t app -p "test_a011_user_privilege.py" -v
```

* テストファイルは `app/tests/acceptance/test_a011_user_privilege.py` として**新規作成する**。

## 【期待結果】

| # | 確認項目 | 期待値 |
| --- | --- | --- |
| 1 | 実行者の権限 | 管理者/root **ではない** |
| 2 | 終了コード | **0** |
| 3 | 標準エラー | 権限に関するエラー(`PermissionError`、`Access is denied`)を含まない |
| 4 | **入力ディレクトリの不変性** | 実行前後でファイル一覧・更新日時が**変わらない**(読むだけである) |
| 5 | **ソースツリーの不変性** | `app/` 配下(`__pycache__` を除く)が実行前後で**変わらない**。特に `app/tests/_work/` が変更されていない |
| 6 | 作業ディレクトリの変化 | `report.md` が作られる。`temp_directory`(既定 `./tmp`)が作られてもよい |
| 7 | **作業ディレクトリの外への書き込み** | 作業ディレクトリと入力ディレクトリの外に、**新規ファイルが作られていない**(ユーザーのホーム、システムの一時領域を除く) |
| 8 | 昇格の要求 | UAC / sudo のプロンプトが出ない(サブプロセスがブロックせずに終了することで確認する) |

**注**: 項目 7 について、Python 自身や DuckDB がシステムの一時領域(`%TEMP%` / `/tmp`)に一時ファイルを作ることは**許容する**。確認の対象は、アプリが意図的に書き込む先である。

## 【合否判定基準】

* **PASS**: 項目 1〜8 が期待値と一致する。
* **FAIL**: 1 項目でも一致しない。**特に項目 4・5(入力とソースツリーを書き換えていないこと)は、運用ログを破壊しかねないため重大である。**
* **BLOCKED**: ビルド確認の失敗、または A001 が FAIL。
* **NOT RUN**: 管理者/root で実行している場合、または権限の確認手段が使えない場合。**その旨を明記し、P302 の「未整備事項・人間による確認事項」へ引き継ぐ。**

## 【失敗時に記録する内容】

* **失敗ログ抜粋**: 終了コード、標準エラー全文。項目 4・5・7 の失敗では、**実行前後のファイル一覧の差分**を全件記録する。
* **再現手順**: 権限の確認方法、入力ディレクトリの読み取り専用化の方法、起動コマンド。
* **影響がありそうなモジュール**:
  * 項目 3 の失敗 → 権限を要求する API を使っている箇所。標準エラーのスタックトレースから特定する
  * 項目 4 の失敗 → **入力ディレクトリへの書き込み**。`loaders` が入力ファイルを開くモードを確認する(`"r"` であるべきで `"r+"` や `"a"` であってはならない)
  * 項目 5 の失敗 → `app/tests/_work/` への書き込み。テストコードまたはアプリが読み取り専用の約束を破っている
  * 項目 7 の失敗 → `reporter.py`(出力先がカレントでない)、`bootstrap.py`(`temp_directory` の解決)
* **テスト指示との矛盾の疑い**: 【事前準備】4 の読み取り専用化が Windows で成立しないことによる失敗は、**アプリの欠陥ではなくテスト指示の問題**である。この場合は「あり」とし、ファイル一覧の比較による代替確認の結果を併記する。
