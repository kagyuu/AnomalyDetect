# 【テストID】A008 — ネットワーク非通信の確認

## 【目的】

* `docs/P001-requirement.md` NFR-008「ネットワーク通信を一切行わない。外部プロセスを起動しない」を確認する。
* **配布先はインターネットに接続されていない閉域環境**である(P000 第2章)。通信を試みると、失敗するだけでなく**長時間のタイムアウト待ちで実行が止まる**。特に DuckDB は既定で未知の拡張を自動ダウンロードしようとするため、これを無効化していることの確認が重要である(`docs/P003-backend-spec.md` DS-14-05)。

## 【対象モジュール】

* `app/src/s_anomaly/bootstrap.py`(拡張自動ダウンロードの無効化)
* 全モジュール(import の静的確認)

## 【前提条件】

* `docs/P009-acceptance-direction.md` 4.1 のビルド確認が成功していること。**失敗した場合は `BLOCKED`。**

## 【使用するテストデータ】

* `app/tests/_work/normal/logs/`(読み取り専用)
* `app/` 配下の全 Python ソース(静的確認の対象)

## 【事前準備】

1. スイート初期化がこのスイートの実行で 1 回だけ済んでいること。
2. 一時作業ディレクトリを作る。

> **本テストの確認方法について** ★ACCEPTED★
> 検討: 実際にネットワークを遮断した環境でアプリを実行して確認する案。**不採用**。検証環境で恒久的にネットワークを遮断すると他の作業に支障が出るため(`docs/P006-test-plan.md` 2.2 の ★ACCEPTED★ と同一の判断)。代わりに **(a) 静的なソース確認 + (b) DuckDB の設定確認 + (c) 実行時のプロセス生成の確認**で行う。残存リスク: DuckDB 内部が拡張以外の経路で通信する場合は見逃す。**閉域環境での初回実行時に人間が確認する項目として P302 へ引き継ぐ。**

## 【実行手順】

**(a) 静的確認**

1. `app/src/` と `app/tools/` と `app/s_anomaly.py` の全 Python ファイルを走査する。
2. 各ファイルを `ast.parse` で解析し、`import` / `from ... import` の対象モジュール名を収集する。
3. 禁止モジュールが含まれていないかを判定する。**文字列の grep ではなく AST で行う**(コメントや文字列リテラル中の言及を誤検出しないため)。

**(b) DuckDB の設定確認**

4. `bootstrap.open_connection` で接続を作り、次の SQL で設定値を取得する。
   ```sql
   SELECT current_setting('autoinstall_known_extensions');
   SELECT current_setting('autoload_known_extensions');
   ```
   * 設定名が存在しない DuckDB バージョンでは例外になる。その場合は**「設定が存在しない = 自動ダウンロード機能が無い」として扱い**、その旨を記録する。

**(c) 実行時の確認**

5. 通常どおりアプリをサブプロセス起動する。
6. 標準エラーに、接続失敗・タイムアウト・プロキシ関連のメッセージが出ていないことを確認する。
7. 実行時間が A001 と同程度であることを確認する(通信のタイムアウト待ちが発生していれば大幅に伸びる)。

## 【実行コマンド】

```
python -m unittest discover -s app/tests/acceptance -t app -p "test_a008_no_network.py" -v
```

* テストファイルは `app/tests/acceptance/test_a008_no_network.py` として**新規作成する**。
