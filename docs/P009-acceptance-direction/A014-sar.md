# A014 — sar(sysstat)取り込みの確認(※CR-010)

* 対象CR: [CR-010](../P901-cr-direction/CR-010.md)
* 実装: `app/tests/acceptance/test_a014_sar.py`
* 対応する要件: **FR-140〜FR-150**(`docs/P001-requirement.md` 4.3a / 13.3 / 10.2a FR-148)

---

## 1. 試験の目的

**アプリを外側から起動し、生成物として確かめる。**

sar 対応は入力種別を 1 つ増やすだけに見えるが、**「取り込みに成功したのに 1 件も検知されない」
という壊れ方をする**。`metrics.DETECTABLE_METRICS` はハードコードの許可リストであり、
ここに漏れがあっても**例外も警告も出ない**。

| 危険 | 起きること |
| --- | --- |
| **`DETECTABLE_METRICS` への登録漏れ** | 取り込みも `metrics` 構築も成功し、**検知だけが 0 件のまま正常終了する** |
| **`SOURCE_KINDS` への登録漏れ** | `[timezone] sar` が「未知のキー」として警告だけ出して無視され、**時差のある環境で突き合わせが静かに全て外れる** |
| **`pct_idle` を ALG-C1 から除外し忘れ** | **閑散なホストが全件「上限に張り付き」**として検知される(誤検知は動いて見える) |
| 後方互換の破壊 | `sa-*.csv` が無い既存利用者の結果が変わる |

**★本試験は「例外が出ないこと」を合格条件にしない。件数を数える。★**
`docs/CLAUDE.md` が記録するとおり、本リポジトリでは同じ型の欠陥が **既に 2 回**起きている。

**既存 3 種別と同じ時刻軸**で生成する(FR-150)。

**4 通り実行する。**

| ラベル | 入力・設定 | 目的 |
| --- | --- | --- |
| `all` | 既定(`activities` は 8 種類すべて) | 本体 |

| `nosar` | `sa-*.csv` を除いたディレクトリ | **後方互換の確認** |
| `tz` | `[timezone] sar = Asia/Tokyo` | 変換経路と警告の確認 |

## 4. #13(後方互換)の確認方法

**「導入前の結果」をどう用意するか**が問題になる。次のようにする。

1. `nosar` 用のディレクトリを、ベースラインから **`sa-*.csv` だけを除いてコピー**して作る。
2. これを実行した結果と、**`all` の結果から sar 由来のイベントを除いたもの**を比較する。
3. **一致しなければ FAIL。** sar の追加が既存の検知・イベント採番・レポート分割に
   影響を与えていることを意味する。

★注意★ **イベント ID の連番は「日 × ホスト」ごとに 1 から振る**(CR-003)。
sar のイベントが同じホスト・同じ日に増えると、**既存イベントの連番がずれる**。
したがって #13 の比較は**イベント ID を除いた内容で**行う。
★ACCEPTED★ **検討したこと**: 連番を種別ごとに分ける案。**採らなかった理由**:
CR-003 が定めた「日 × ホスト」の体系を変えることになり、既存のレポートとの互換が切れる。
**残存リスク**: sar を導入すると既存イベントの ID が変わる。**これは仕様であり、
利用者に説明が要る**(`README.md` に記載する)。
