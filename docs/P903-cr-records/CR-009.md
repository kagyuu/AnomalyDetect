検討のうえ**自前生成を選んだ**。決定的だったのは次の事実である。

```
$ ls app/vendor/
(空)
```

`docs/P302-deliver.md` の **FR-002-実環境 は BLOCKED**。理由は
「**配布先の Python 版が未確認のため、同梱すべき wheel を確定できない**」。
**DuckDB ですら同梱できていない。** C 拡張を持つ依存を足すと、この未解決問題が
1 個から数個に増える。詳細は `docs/ADR.md` **ADR-020**。

## 3. 事前のスコープ想定と実際の差異

### 3.1 **重ね合わせが構造的に一度も描かれなかった**

**これが本CRで最も重要な発見である。**

最初の実装では、対象イベントを**脅威度の高い順だけ**で選び、既定を
`min_severity = SEVERE` とした。動かしたところ 15 枚のチャートが出たが、
**全ての図で折れ線が 1 本しかなかった。**

原因は設計上の衝突である。

| 事実 | 出典 |
| --- | --- |
| **`SEVERE` は定義上「観点2 の検知」である** | `README.md` 5 章 / DS-09-04 |
| **観点2 のイベントには同時アノマリーが付かない**(`co_anomalies` が None) | CR-002 / DS-11-08 |

**したがって `SEVERE` だけを対象にすると、重ね合わせの相手が原理的に存在しない。**
**依頼者の要求の半分が、エラーを出さずに消えていた。**

**是正**: 選別の枠を 2 つに分けた。

```
枠1: 脅威度の高い順                        … max_per_host 件/ホスト
枠2: 同時アノマリーを持つイベントの脅威度順  … max_overlay_per_host 件/ホスト
```

あわせて**既定を `FATAL` に変えた**(`SEVERE` のままでは枠 2 が空になる)。
是正後、14 日のベースラインで 59 枚中 複数枚に重ね合わせが出ることを確認した。

**回帰試験**: `test_overlay_quota_is_separate`(単体)と
`test_05_overlay_charts_are_actually_produced`(A013)。

**教訓**: CR-002 で「原因候補ルールが無言で発火しなくなった」のと**同じ型の欠陥**である。
**「設定の既定値が、別の機能の前提と噛み合っていない」**という形で現れる。

### 3.2 採取間隔の違いで横軸がずれた

重ねる相手の系列は採取間隔が違うため、そのまま並べると横軸が合わない。
**本体の時刻列に合わせ、同じ時刻の点が無ければ直前の値を保持する**(階段状)ようにした。

### 3.3 A011(一般ユーザー権限)が落ちた

作業ディレクトリの生成物を `report_*` と `tmp/` に限っていたため、
`charts/` が「想定外の生成物」と判定された。**期待値に `charts/` を加えた。**
A011 の主眼は「作業ディレクトリの外へ書かないこと」であり、そちらは変えていない。

### 3.4 追加の指示(2026-09-06)

**実装後、依頼者から 3 点の追加指示があった。**

| # | 指示 | 対応 |
| --- | --- | --- |
| 1 | **チャートが出ていないと「ツールの不備」と誤解される。** `[NO CHART]` の画像を出す | `charts/no-chart.svg` を **1 つだけ**作り、全イベントから参照 |
| 2 | **理由は書かない**(4K トークンの制限に抵触しうる) | 画像は `[NO CHART]` の文字のみ |
| 3 | **`MIN_POINTS` が原因の場合は生データを表で出す** | `[NO CHART]` に続けて `| 時刻 | 値 |` の表 |
| 4 | README に `MAX_POINTS` / `MIN_POINTS` を記載(設定化は不要) | README 4.5 に節を追加 |

**設計上の判断**: **チャート機能が無効(`enabled = false`)のときは画像を出さない。**
誰も図を期待しない状況で `[NO CHART]` を 7,000 件並べる意味がないためである。

### 3.5 上限の既定値を 100 + 100 に変更(2026-09-06)

依頼者の指示により `max_per_host` / `max_overlay_per_host` を 10 → **100** にした。

| 設定 | 枚数(30 日 / 17 ホスト) | 合計サイズ | 実行時間 |
| --- | --- | --- | --- |
| 10 + 10 | 340 枚 | 3.7MB | 55.3s |
| **100 + 100** | **2,429 枚** | **17.8MB** | **103.2s(+87%)** |

**A006 の上限判定を設定から導くように変えた。** 直値(`17 * (10 + 10)`)で
書いていたため、既定値を変えると試験が壊れる状態だった。
