### マイグレーション方式の確認(「データモデル変更」に該当)

* **`docs/P003-backend-spec.md` に記載されている適用方式**: `app/src/s_anomaly/schema.py` の `DDL` を起動時に全件実行する。各文は `CREATE TABLE IF NOT EXISTS` である。
* **その方式は冪等か**: **冪等である。** 理由は 2 つある。
  1. すべて `CREATE TABLE IF NOT EXISTS` であり、2 回実行しても失敗しない。
  2. **そもそも DuckDB のデータベースを永続化しない**(P001 17章「分析結果の永続化・履歴管理」は対象外)。実行のたびに新しいデータベースを作るため、既存スキーマとの差分適用という問題自体が発生しない。
* **冪等化を本CRの対応範囲に含めるか**: **不要。** 本CRが行うのは**テーブルの追加**(`sar`)のみであり、`ALTER TABLE ... ADD COLUMN` のような条件付き実行の構文を持たない DDL は追加しない。既存テーブルの定義も変更しない。
* **確認方法**: 実装後に、**同一ディレクトリに対して `s_anomaly.py` を 2 回連続で実行し、2 回目も成功すること**を確認する(結果はテスト記録に残す)。これは既存の A011 と同じ確認経路である。

### 着手前に見えている risk(実装中に確認する)

| # | risk | 確認方法 |
| --- | --- | --- |
| 1 | **系列数の増加で NFR-002(600 秒)を超える** | A006(性能テスト)を 90 日規模で実測する。超えた場合は人間に報告し、既定値を狭めるか「次のCRの候補 #1」を起票するかの判断を仰ぐ |
| 2 | **sar の比率メトリクスが無言で検知対象から外れる** | `metrics.DETECTABLE_METRICS` はハードコードの許可リストであり、**`RATIO_METRICS` 側に入れると検知されない**。`docs/CLAUDE.md` が記録する「設定の既定値が別の機能の前提と噛み合わず、エラーを出さずに機能が消える」欠陥(CR-002・CR-009 で 2 回発生)と同じ型である。**「sar 由来のイベントが実際に 1 件以上検知される」ことを確認する受け入れテストを必ず書く。** 例外が出ないだけのテストにしない |
| 3 | **`pct_idle` が全ホストで ALG-C1 に引っかかる** | FR-148 の除外が効いていることを、閑散なホストのテストデータで確認する(FR-111 に追加済み) |
| 4 | **ALG-C1 の `MIN_DISTINCT_VALUES` / `min_spread` が sar の比率で意図せず効く** | `pct_util` のように 0 付近で推移し稀に跳ねる系列は変動幅が大きく問題ないが、常時 99〜100 の系列は `min_spread`(1.5 倍)を満たさず**検知されない**。実装時に確認する |

### スコープの妥当性

**CR-010 が持ち込んだものではない。** スコープ判断の誤りには当たらない。

### 反映確認の結論

**14 項目すべてを確認できた。不足は無い。**

**とくに #7(実際に検知されること)は、単体・結合・受け入れの 3 層すべてで
「件数が 0 でないこと」として検証している。** `docs/CLAUDE.md` が記録する
「機能を足したら、実際にその機能が動いた証跡を確認するテストを書くこと。
『例外が出ない』だけでは通ってしまう」という規則への対応である。

| --- | --- | --- |
| **ADR-022** | **sar が直接出力する比率(`pct_*`)は一次の検知対象とする。ADR-005 の「`*_pct` は検知対象外」は、本アプリが導出した使用率についての規則である** | **知らずに触ると静かに壊れるため。** `metrics.DETECTABLE_METRICS` はハードコードの許可リストであり、sar の比率を `RATIO_METRICS` 側へ入れると**例外も警告も出ないまま 1 件も検知されない**。「`*_pct` は対象外」という ADR-005 の記憶だけで判断すると、まさにその事故が起きる |
| **ADR-023** | **`sar` テーブルは縦持ち(long)で持つ。活動種別ごとの横持ちテーブルを作らない** | 後任が「他の 3 テーブルに合わせて横持ちにすべきでは」と考えるのが自然であるため。`sadf` の列は sysstat の版で増減し、横持ちにすると版が変わるたびにテーブル定義の変更が要る |
