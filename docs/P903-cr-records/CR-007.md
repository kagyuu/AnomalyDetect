## 2. 変更した箇所

**`cli.detect` のループの向きを変えた。** これが CR-006 と CR-007 に共通する唯一の変更である。

```python
# 変更前 — 検知器ごとに全系列を回る (同じ系列を 11 回読む)
for detector in active:
    for meta in series:
        detector.run(con, cfg, meta, progress)

# 変更後 — 系列ごとに全検知器を適用する (読むのは 1 回。系列がスレッドの単位)
for meta in series:                # ThreadPoolExecutor で分配
    base.begin_series(meta)
    for detector in active:
        detector.run(cursor, cfg, meta, progress)   # cursor はスレッド固有
    base.end_series()
```

CR の予測どおり、**対処が要ったのは `failures` の 1 箇所だけ**であった。

| 出力 | 対処 |
| --- | --- |

**全 18 ファイルが「実行日時」の行を除いて完全一致**した。
`TestA003ThreadCountDoesNotChangeOutput` が回帰試験である。

## 4. メモリへの影響 — CR の ★FIXME★ に対する回答

**CR には「スレッドごとに `con.cursor()` を持つとメモリ使用がどう変わるか実測すること」と
書かれていた。前回 S8 で OOM(終了コード 6)を起こしたばかりであるため、確認した。**

| 規模 | `max_memory` | スレッド | 結果 |
| --- | --- | --- | --- |
| 30 日(950,400 行) | 4GB(既定) | 8 | **終了コード 0** |
| 90 日(2,851,200 行) | 4GB(既定) | 8 | **終了コード 0** |

**`con.cursor()` は接続を複製しない。** DuckDB の `max_memory` はデータベース単位の設定であり、
カーソルはその上のハンドルにすぎない。A006 の `test_06_no_memory_error` と
A007(メモリとスピル)が既存の回帰試験として働いている。**★FIXME★ は解消した。**

## 5. 事前の想定と実際の差異 — 速度比が 5.68 倍にならなかった

**CR は「CR-006 + CR-007 で 5.68 倍」と見込んでいたが、実際は 1.13 倍であった。**

| 構成(30 日規模 / S6 の壁時計) | 1 スレッド | 8 スレッド | 速度比 |
| --- | --- | --- | --- |
| **SQL 実装の検知器のみ**(A3 / A5 / B5 / C1) | 10.5s | 5.9s(4 スレッド) | **1.78x** |
| **全 11 検知器** | 26.3s | 23.2s | **1.13x** |

**理由は 2 つある。**

1. **純 Python の処理は GIL により並列化されない。** 11 検知器のうち 7 つが純 Python であり、
   ここがスレッドで速くならない。**これは CR が予測していたとおりである。**
2. **その 7 つを SQL へ移す前提が崩れた。** CR-006 の実測により、系列単位の SQL 化は
   かえって遅いと分かり採らなかった(`docs/P903-cr-records/CR-006.md` 2.2)。
   **CR-007 の効果が限定されたのは、対の CR-006 が前提どおりに進まなかったためである。**

また、起票時の微小ベンチマーク(5.68 倍)は**純粋な SQL 処理**を測ったものであり、
実際の S6 は SQL と Python が混ざる。**混合した処理での実測が 1.78 倍・1.13 倍である。**

★ACCEPTED★ **1.13 倍で受け入れる。** 検討したのは
(a) 全系列を 1 クエリで処理する方式へ移す(CR-006 4章。設計が衝突し、メモリ影響の実測が要る)、
(b) `multiprocessing` へ移る(CR-007 備考で既に棄却済み)である。
残存リスクは**無い**(遅くはならず、SQL 主体の検知器が増えるほど効きが増す)。
**系列数の増加への備えという本CRの目的は、CR-006 のキャッシュが達成している**
(1 系列あたり 1.2 秒 → 0.16 秒。500 系列でも S6 は約 80 秒)。
