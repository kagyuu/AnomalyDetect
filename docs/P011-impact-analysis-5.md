# P011 影響分析 — P010(5 回目)の矛盾点

* 版: P010 5 回目(CR-010)に対する影響分析
* 入力: `docs/P010-design-review-5.md`
* 対象フェーズ: **P903 内部の P011**

## 1. 分析の方針

`docs/P010-design-review-5.md` 3章の 6 件について、次を明らかにする。

1. **正とすべき記述はどちらか**(判断の根拠を上位文書に求める)
2. **修正が必要な箇所**
3. **波及先**
4. **P012 での修正担当文書**

**6 件はいずれも文書内の記述の不整合であり、設計判断そのものの見直しを要するものは無い。**
したがって P002〜P009 の設計内容(何を作るか)は変わらない。

### 2.1 #1 — `[sar] activities` の「違反時」列(重大度: 中)

| 項目 | 内容 |
| --- | --- |

| **根拠** | P001 FR-149 が「未知の活動名は FR-083 と同じく警告を出して無視する」と定めている。**FR-083 は上位の要求であり、P002 の表の「違反時」列より優先する** |

`raise` を書くと、**設定を書き間違えただけで解析が止まる**。A014 #12 で捕まるが、
その前に設計を直すほうが安い。

### 2.2 #2 — `await` が Python の予約語(重大度: 中)

| 項目 | 内容 |
| --- | --- |
| **正とすべき記述** | メトリクス名は `await` のまま(sar の列名に合わせる)。**変えない** |
| **根拠** | P001 FR-143 の正規化規則は `%` `/` `-` のみを対象としており、予約語の回避を含まない。**メトリクス名は文字列としてしか現れない**(辞書のキー・SQL の値)ため、名前を変える理由が無い。むしろ変えると sar の列名との対応が読めなくなる |
| **修正箇所** | `docs/P007-impl-direction/U010-sar.md` §4.5 に注意書きを足す |
| **波及先** | 無し |
| **担当** | P012 |

★ACCEPTED★ **`await` という名前を避けない。** **検討したこと**: `io_await` などに改称する案。
**採らなかった理由**: sar の列名との 1 対 1 の対応が失われ、レポートを読む運用者が
`sar -d` の出力と突き合わせられなくなる。**残存リスク**: 実装者が識別子として使うと
構文エラーになる。**これは即座に気付ける誤りであり、静かに壊れない。**
