# CR-011 — sar の NFS / NFSD 統計を分析対象に追加する

## 起票日

2026-09-08

## 起票者

依頼者(本リポジトリの発注者)。会話による直接の指示。

* 2026-09-08 「**sar のうち NSFD NSF は評価対象ですか? 対象システムでは極めて重要な指標です
  (LSF 計算グリッドが、NFS でファイルを共有するため)。もし、対象になっていなければ、
  次の改善要望で実現します(今回の改善には入れなくていいです)**」 — CR-010 の実施中に指摘
* 2026-09-08 「**NFS NFSD の追加をお願いします**」 — 変換スクリプトへの追加を指示
* 2026-09-08 「**CR-011 として起票して、実装・テスト・納品物作成までお願いします**」 — 本CRの直接の起票契機

**入力方式はプロンプト方式である**(`docs/P900-change-concept.md` は作成していない)。

## 背景・課題

**CR-010 で sar を分析対象に加えたが、NFS / NFSD 統計は範囲外とした**(依頼者が明示)。
その結果、いまは次の状態にある。

| 層 | 状態 |
| --- | --- |
| 変換スクリプト(`README.md` 付録A `sa2csv.sh`) | **`-n NFS` / `-n NFSD` を出力する**(2026-09-08 に追加済み) |
| 本アプリ | **読み込まない。** 未知の活動種別として読み飛ばし、1 ファイルにつき WARNING が 2 行出る |

**この状態は 2 つの意味で望ましくない。**

| # | 内容 |
| --- | --- |
| 1 | **対象システムで最も重要な指標のひとつが分析されていない。** 依頼者の言葉では「**LSF 計算グリッドが NFS でファイルを共有するため、極めて重要**」である。**NFS の詰まりは、LSF のジョブ滞留(`bqueues` の `pend` 増加)の直接の原因になりうる**が、いまはその突き合わせができない |
| 2 | **採取しているのに読み飛ばすため、実行のたびに警告が出続ける。** 30 日分で標準エラーに 60 行ほど出る。**本来の警告が埋もれる** |

**CR-010 の主目的は「アプリ層の異常と OS 資源の異常を突き合わせること」であった。**
NFS は、その突き合わせの鎖の中で**いちばん切れやすい環**である。

## 変更要求の内容

**`sadf -d ... -- -n NFS` / `-n NFSD` が出力するブロックを取り込み、
既存の 11 アルゴリズムの検知対象に加える。**

### 前提(CR-010 で確立済み。本CRで蒸し返さない)

* 入力ファイルは `sa-{ホスト名}-{yyyymmdd}.csv`(変更なし)
* 系列キーは `sar/{ホスト名}/{活動}/{デバイス}`(変更なし)
* 列名の正規化規則(`%` → `pct_` 接頭、`/` `-` → `_`)は変更なし
* **`sar` テーブルは縦持ちである**(ADR-023)。**テーブル定義の変更を伴わない**
* 未知の活動種別・未知の列は読み飛ばす(変更なし)

**したがって本CRは「活動種別を 8 → 10 に増やす」ことに尽きる。**
新しいモジュールもテーブルも要らない。

### 本CRで決めること

| # | 論点 | 提案 |
| --- | --- | --- |
| 1 | 活動の名前 | **`nfs`(クライアント)と `nfsd`(サーバ)** |
| 2 | 取り込むメトリクス | 下表。**`-n NFS` は 6 列すべて、`-n NFSD` は 11 列中 8 列** |
| 3 | 既定の `[sar] activities` に含めるか | **含める。** 依頼者が「極めて重要」と明示している |
| 4 | ALG-C1(観点3)の扱い | **全 14 メトリクスを対象外とする。** いずれも毎秒のレート値であり、**上限が自明でない** |

### 取り込むメトリクス

| 活動 | `sadf` の指定 | メトリクス | 選定理由 |
| --- | --- | --- | --- |
| `nfs` | `-n NFS` | `call_s` | クライアントが出した RPC 要求の総量。負荷そのもの |
| | | **`retrans_s`** | **再送。NFS の不調が最初に現れる指標である**(サーバの遅延・パケット損失) |
| | | `read_s` / `write_s` | 読み書きの比率。ジョブの性質の変化を映す |
| | | `access_s` / `getatt_s` | **メタデータ操作。小さなファイルを大量に扱うグリッドで詰まりやすい** |
| `nfsd` | `-n NFSD` | `scall_s` | サーバが受けた RPC 要求の総量 |
| | | **`badcall_s`** | **不正な要求。エラーの直接の指標である** |
| | | `hit_s` / `miss_s` | **応答キャッシュの命中/失敗。`miss_s` の上昇はサーバ側の逼迫を示す** |
| | | `sread_s` / `swrite_s` | サーバ側の読み書き |
| | | `saccess_s` / `sgetatt_s` | サーバ側のメタデータ操作 |

**`-n NFSD` の `packet_s` / `udp_s` / `tcp_s` は取り込まない。**
`scall_s` と重複した情報であり、**トランスポートの内訳は不調の指標にならない**ためである。
★FIXME★ (この 3 列を落とす判断は Agent のものである。実データで確認が要る)

**メトリクス名は既存のどれとも衝突しない**(確認済み)。

## 期待する振る舞い

* `sadf -d ... -- -n NFS` のブロックが **`nfs` として判別され**、6 メトリクスが `sar` テーブルへ入る。
* `sadf -d ... -- -n NFSD` のブロックが **`nfsd` として判別され**、8 メトリクスが `sar` テーブルへ入る。
* `series_id` は **`sar/{host}/nfs/-` / `sar/{host}/nfsd/-`** になる(いずれもデバイス列を持たない)。
* **既存の 11 アルゴリズムが nfs / nfsd の系列にも適用され、埋め込んだ異常がイベントとして検知される。**
* **`retrans_s` の異常が、同一ホストの LSF のジョブ滞留と同じ時間帯にレポートへ現れる**(NFS の詰まりがジョブ滞留の原因になりうる、という突き合わせができる)。
* レポートの「データ」欄に **NFS のメトリクスの和名**が出る。
* **ALG-C1 が nfs / nfsd のメトリクスを「上限への張り付き」として検知しない**(上限が自明でないため)。
* **既定の `[sar] activities` に `nfs` と `nfsd` が含まれる。** 設定で絞れる。
* **NFS の統計を含まない `sa-*.csv`(CR-010 までの形式)でも、従来どおり動作する**(後方互換)。
* **「未知の活動種別」の WARNING が、NFS / NFSD について出なくなる。**
* 値がすべて 0 の系列(NFS サーバでないホストの `nfsd`)でも、**実行が止まらず、誤検知も出ない。**

## 影響が想定される範囲

P901時点での見積もりであり、確定した対応範囲ではない。

* **画面(CLI)**: 起動ログの系列数が増える。`[sar] activities` の既定値が変わる
* **データモデル**: **変更なし。** `sar` テーブルは縦持ちであり、活動と メトリクスが増えるだけである(ADR-023 の利点がそのまま効く)
* **モジュール**: `loaders/sar.py`(`ACTIVITY_RULES` / `WANTED`)、`metrics`(`DETECTABLE_METRICS`)、`config`(`SAR_ACTIVITIES`)、`detectors/c1_saturation`(`NO_CEILING`)、`reporter`(`METRIC_LABELS`)。**新規ファイルは無い**
* **テスト**: `gen_testdata` に nfs / nfsd の生成と異常の埋め込み。単体・T009・A014 の拡張
* **文書**: `README.md`(付録A の「まだ読み込まない」節を書き換える。4.6 の表)、`docs/P001-requirement.md` 4.3a / 13.3、`docs/P003-backend-spec.md` 5.4a

## 優先度の判断理由

**優先度: 高。**

* **影響度: 高** — **対象システムで最も重要な指標のひとつ**であると依頼者が明示している。
  LSF のジョブ滞留の原因分析に直結する。
* **緊急度: 高** — **回避策が無い**(データは貯まっているが読めない)。
  加えて、**読み飛ばしの警告が出続けて本来の警告が埋もれる**という実害が既に発生している。

ルーブリック(影響度: 高 × 緊急度: 高)より **優先度: 高**。
