# CR-003 — イベント ID の体系を `EVT-YYYYMMDD-{HOST}-999` にする

## 起票日

2026-09-05

## 起票者

本アプリの依頼者(会話による指示。2026-09-05)

## 背景・課題

**現状**: イベント ID は `EVT-{異常の開始日 YYYYMMDD}-{その日の連番 3 桁}` である
(`docs/P001-requirement.md` FR-072、`app/src/s_anomaly/events.py::assign_event_ids`)。

```python
event.event_id = "EVT-{0}-{1:03d}".format(day, counters[day])
```

例: `EVT-20260601-001`

**困りごと**: 連番が**日単位で全ホスト共通**に振られているため、**ID からホストが分からない**。

CR-001 で `report.md` をホスト × 年月に分割すると、この問題が実害になる。

* あるファイルに載っているイベント ID を見ても、それがどのファイルのものか判別できない。
* CR-002 の「同時に発生したアノマリー」欄は**他ホストのイベントを参照する**ため、
  参照先の ID を見ただけではどのファイルを開けばよいか分からない。**分割の利点が損なわれる。**

## 変更要求の内容

**イベント ID を `EVT-{YYYYMMDD}-{HOST}-{連番 3 桁}` に変更する。**

* 例: `EVT-20260601-host01-001`
* 対応する既存の仕様箇所:
  * `docs/P001-requirement.md` **FR-072**、**12章**(`# イベントID( EVT-YYYYMMDD-999 )` の書式例)
  * `docs/P002-frontend-spec.md` **UI-04** 4.2(イベント ID の項目仕様。198 行・217 行・245 行に書式例と規則)
  * `docs/P003-backend-spec.md` **DS-09-07**(採番規則)

## 期待する振る舞い

* イベント ID が `EVT-{開始日 YYYYMMDD}-{ホスト名}-{連番 3 桁}` の形式になる。
* **連番は「日 × ホスト」ごとに 1 から振られる**(日単位の全ホスト通し番号ではない)。
* 同一の入力に対して、常に同一の ID が振られる(NFR-009 の再現性)。
* ホスト名が特定できない系列がある場合でも、実行が失敗しない。
* CR-002 の「同時に発生したアノマリー」欄に載る相手の ID から、**その相手がどのホストのものか**が読み取れる。
* イベント ID が 1 実行の中で重複しない。

## 影響が想定される範囲

* 画面: 該当なし
* API: 該当なし
* データモデル: 変更なし
* モジュール: `app/src/s_anomaly/events.py`(`assign_event_ids`)、`app/src/s_anomaly/reporter.py`(表示)、`app/src/s_anomaly/correlate.py`(`_event_windows` のキー。ただし CR-002 で廃止予定)
* テスト: `app/tests/unit/test_events.py`(採番規則)、`app/tests/integration/report_parser.py`(ID の解析)、**T006**、**A001**、`app/tests/_work/normal/expected.json`
* 関連ADR: 抵触するものは無い
* **CR-001 / CR-002 との関係**: 本 CR は両者と**同時に適用されることを前提とする**。CR-001(ホスト分割)が無ければ ID にホストを含める動機が弱く、CR-002(他ホストのイベントを参照する欄)があることで実益が生じる

## 優先度の判断理由

**影響度: 低 / 緊急度: 高 → 優先度: 中**

* 影響度: ID の表記だけの変更であり、検知の内容・レポートの構成には影響しない。
* 緊急度: CR-001 / CR-002 と同時に入らないと、分割したファイル間の相互参照が辿れなくなる。

★FIXME★ ホスト名を ID に含めると ID が長くなる(例: `EVT-20260601-host01-001` は 29 文字)。
ホスト名の長さに上限を設けるか、そのまま使うかは人間の確認が必要である。

## 備考

* 実測(30 日規模)では、ホストは **17 種**、1 ホスト 1 日あたりのイベントは最大でも 3 桁に収まる範囲であり、**連番 3 桁で足りる**見込みである。
* ホスト名は系列 ID から抽出する。既存の `app/src/s_anomaly/correlate.py::extract_host` が 3 書式(`db_connection` / `jvm_gc` / `lsf_queue`)に対応済みであり、これを流用できる。**ただし CR-002 で `correlate.py` を大きく変更するため、関数の置き場所を見直す必要がある。**
