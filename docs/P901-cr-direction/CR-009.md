# CR-009 — アノマリー発生時の状況を SVG の折れ線チャートで出力する

## 起票日

2026-09-06

## 起票者

本アプリの依頼者(会話による指示。2026-09-06)

## 背景・課題

**現在のレポートは数値と文章だけである。** イベントには「値」欄があるが、
**9 点に間引いた値**しか持たない(`sample_values`)。

```
* 値           : 55.0→56.2→58.1→…→69.4→71.3
```

**これでは「どういう形で異常だったのか」が分からない。** 一気に跳ねたのか、
階段状に上がったのか、上限に張り付いたのかは、時系列の形を見ないと判断できない。

**とくに「同時に発生したアノマリー」(CR-002)で相手が分かっても、
その相手がどう動いていたかを見る手段が無い。** 相手のレポートを開いて
9 点の数値列を読むしかない。

## 変更要求の内容

### 1. アノマリー発生時の状況を折れ線チャートにする

**SVG ファイルとして出力し、Markdown のレポートから画像リンクで参照する。**

```markdown
![host01 ou の推移](charts/EVT-20260605-host01-015.svg)
```

### 2. 同時期に起きている他のアノマリーを重ね合わせる

**同じ時間軸で、「同時に発生したアノマリー」(CR-002)の系列を重ねる。**

## 期待する振る舞い

* **同一入力・同一設定なら、SVG もバイト単位で一致する**(NFR-009)。
* **外部ライブラリを増やさない**(FR-003)。SVG は自前で生成する。
* **サマリ(`report_summary_*.md`)は変えない。** 4K トークンの目標(CR-004)を守る。
* **チャートを出す件数に上限を設けられる。** 既定では出しすぎない。
* **日本語のラベルが出る。**
* リンクは**相対パス**とする(レポートは別の場所へ移されうる)。

## 方式の選定(2026-09-06 の検討)

**依頼者は当初「チャート作成ライブラリを追加してもよい」としたが、
検討の結果、自前生成を選択した。**

| 方式 | 判断 | 理由 |
| --- | --- | --- |
| **自前生成の SVG** | **採用** | 下記 |
| 純 Python ライブラリ(pygal 等) | 不採用 | wheel は 1 つで済むが、自前生成に対する利得が小さい |
| matplotlib | **不採用** | 下記 |

### matplotlib を採らなかった理由

**`app/vendor/` は空であり、閉域環境への同梱経路そのものがまだ実証されていない**
(`docs/P302-deliver.md` FR-002-実環境 = **BLOCKED**)。
理由は「**配布先の Python 版が未確認のため、同梱すべき wheel を確定できない**」ことである。
**DuckDB ですら同梱できていない。**

C 拡張を持つライブラリを足すと、この未解決問題が 1 個から数個に増える。加えて

| # | 具体的な問題 |
| --- | --- |
| 1 | wheel が **OS × アーキ × Python マイナー版**ごとに要る(matplotlib + numpy + pillow ほかで 1 組み合わせ 35〜50MB) |
| 2 | **日本語が豆腐になる。** 既定フォントに CJK が無く、CJK フォントの同梱とライセンス確認が要る |
| 3 | **ホームディレクトリにフォントキャッシュを書く。** 「書き込み先はカレントディレクトリと `temp_directory` のみ」(README 2.1)を壊しかける |
| 4 | SVG に日付メタデータと可変の要素 ID を埋めるため、**そのままでは実行ごとにバイト列が変わる**(NFR-009) |
| 5 | **FR-003 の改訂と A008(import 許可リスト)の緩和**が要る。要件を緩める判断は人間のものである |

**SVG をテキストとして自前生成すれば、上記はすべて発生しない。**
とくに **2 は SVG の構造的な利点**である。文字は閲覧側のフォントで描画されるため、
こちらでフォントを同梱しなくても日本語が出る。

## 影響が想定される範囲

* 画面: **ホスト別レポートのイベント本文**(`docs/P002-frontend-spec.md` 4章)。
  **サマリは変えない。**
* データモデル: 変更なし。**`metrics` から描画用の点列を引き直す**
* モジュール:
  * **新規** `app/src/s_anomaly/charts.py`(SVG の生成)
  * `app/src/s_anomaly/events.py`(`Event` にチャートのパスを持たせる)
  * `app/src/s_anomaly/reporter.py`(画像リンクの出力)
  * `app/src/s_anomaly/cli.py`(チャート生成の呼び出し)
  * `app/src/s_anomaly/config.py`(件数の上限などの設定)
* 設定: **新しいセクション `[chart]`**
* テスト: 単体(SVG の生成)、結合(リンクとファイルの対応)、受け入れ(疎通)
* 関連ADR: **新規 ADR の候補**(チャートを自前生成する判断と、その理由)

### 実測にもとづく制約(2026-09-06)

**試作して確認した。**

| 確認したこと | 結果 |
| --- | --- |
| 実データからの折れ線描画 | **できる**(3 日分 865 点で確認) |
| **ASCII での重ね合わせ** | **実用にならない。** 3 系列を重ねると記号が散らばって線を追えない |
| 同一時間軸に細い折れ線を積み上げる形 | 読める |
| **30 日規模のイベント数** | **7,229 件**(SEVERE 416 / FATAL 2,898 / WARN 3,915) |

**全件にチャートを付けてはならない。** ASCII で 1 枚 1KB としても +7MB になり、
現在のホスト別レポート合計(約 5MB)を超える。**既定は SEVERE のみとする。**

## 優先度の判断理由

**影響度: 中 / 緊急度: 中 → 優先度: 中**

* 影響度: レポートの読み方が変わるが、**既存の出力を壊さない**(追加のみ)。
* 緊急度: 運用を止めている問題ではない。**判断の質を上げるための改善である。**

## 備考

★ACCEPTED★ **チャートは人間向けであり、後段の LLM 向けではない。**
CR-004 で「4K トークンのローカル LLM が集計できる」ようにしたのが現在の設計だが、
**SVG は LLM からは見えない。**
検討したのは ASCII のチャートをレポート本文に埋める案。
**採らなかった理由**: (a) 重ね合わせが実用にならない(上記の実測)、
(b) トークンを消費するのに LLM の判断には寄与しない、
(c) レポート本体が肥大する。
**残存リスク**: LLM だけで完結する運用では、チャートの情報は使われない。
**サマリを変えないため、その運用は現在どおり成立する。**
