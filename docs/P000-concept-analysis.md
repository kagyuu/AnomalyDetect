## 5. コマンドごとの定義 【必須】

### C01 s_anomaly.py {dir}

#### 書式

{dir} 以下のログファイルから異常値を発見する。異常値の報告はカレントディレクトリに repot.md を出力する

#### 処理内容

1. 指定された {dir} を再帰的にたどってログファイルの内容を DuckDB (オンメモリ) に格納する
   
   JavaEEサーバの jstat については、次の項目のテーブルに解釈しなおして格納する
   
   time コンテナ名 ホスト名 SOC SIC SOU SIU EC EU OC OU MC MU CCSC YGC YGCT FGC FGCT GCT
   
   LSF (計算グリッド) のキューの状態については、次の項目のテーブルに解釈しなおして格納する
   
   time,ホスト名,QUEUE,NJOBS,PEND,RUN,SUSP

2. DuckDB から異常値をピックアップしてください

   異常値の観点は二つです。それぞれに観点を満たす、具体的な異常値の発見アルゴリズムは、代表的なものを実装してください。
   
   観点1) 瞬間的な外れ値                       : 例 移動平均乖離率 (2σ、3σ)
   観点2) 持続的な数値の増加(メモリリークなど) : 例 長期の移動平均よりも短期の移動平均が常に上にある

3. 見つかった異常値をカレントディレクトリの report.md に出力してください。

#### 出力

| 出力先 | 内容 |
| --- | --- |
| 標準出力 | 動作ログを出力してください(長期に動くので、どこまで進んでいるか、今何をしているのか分かるようにしてください) |
| 標準エラー出力 | 動作ログを出力してください |
| ファイル | report.md |

report.md は、この後 LLM に食べさせて、運用レポートを作らせます。
各異常値にについて次の事柄を出力してください

```
# イベントID( EVT-YYYYMMDD-999 )

( イベント種別 : {どのアルゴリズムに基づく異常値か}
* 脅威度 : {INFO,WARN,FATAL,SEVERE}
* データ : {どのデータか}
* 値     : {どのような値か 例: 3→5→2→20→21 }
* 開始   : {異常の開始時刻}
* 終了   : {異常の終了時刻}
* 現象   : {状況説明 例:最低値が14日上昇し、回復しない、負荷増はない}
* 説明   : {なぜ異常と判断したか}
* 原因候補 : {原因として考えられることを確立付きで述べる}
* 同時刻のその他のデータ : {同時刻のその他のデータの状況を述べる}
```
