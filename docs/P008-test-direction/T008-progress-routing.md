# 【テストID】T008 — 進捗ログの出力先振り分け

* 単体テスト(U001-T2)では `progress` 単体の振る舞いを確認しているため、ここでは**パイプライン全体を通したときのログの網羅性**を見る。

## 【事前準備】

1. スイート初期化がこのスイートの実行で 1 回だけ済んでいること(T001 参照)。
2. `tempfile.TemporaryDirectory` で作業ディレクトリを作り、`os.chdir` で移動する。**`addCleanup` で必ず元に戻す。**
3. `cli.main(argv, stream_out=io.StringIO(), stream_err=io.StringIO())` の形で、**出力先を差し替えて呼ぶ**(U001-T5 で用意したシグネチャ)。プロセス起動は行わない。

## 【実行手順】

**手順 A: 正常系**

1. `main([str(app/tests/_work/normal/logs)], stream_out=out, stream_err=err)` を実行する。
2. `out` と `err` の内容を行に分解する。
3. ステップ ID の出現、書式、振り分けを検証する。

**手順 B: WARNING が出る系**

4. 新しい `StringIO` を用意し、`main([str(app/tests/_work/broken/logs)], ...)` を実行する。
5. `err` に WARNING が出ていること、`out` に WARNING が出て**いない**ことを検証する。

**手順 C: 二重出力の確認**

6. 同一プロセス内で `main` を **2 回**呼ぶ(手順 A を 2 回)。
7. 2 回目の出力行数が 1 回目とほぼ同じであり、**倍になっていない**ことを確認する(`logging` のハンドラ二重登録の検出)。
