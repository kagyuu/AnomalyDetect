# S_ANOMALY — レポート出力のサンプル

**運用ログの異常検知ツール `S_ANOMALY` が実際に出力したレポート群である。**
手で書いたものではなく、受け入れテスト(A006 大規模データでの完走と実行時間)を
実行して生成されたものをそのまま置いてある。

> **入力は合成データである。実データではない。**
> `gen_testdata.py` が既知の異常を既知の位置に埋め込んで生成したログを解析している。
> ホスト名・データソース名も含め、**実在するシステムの情報は一切含まない。**

---

## 中身

| ディレクトリ | 規模 | レポート | チャート |
| --- | --- | --- | --- |
| `normal-30d/` | 通常のユースケース(30 日 / 950,400 行 / 17 ホスト) | 18(ホスト別 17 + サマリ 1) | 2,430 枚 |
| `large-90d/` | 大規模ケース(90 日 / 2,851,200 行 / 17 ホスト) | 54(ホスト別 51 + サマリ 3) | 2,430 枚 |

**`.md` と `charts/` は一緒に置いたままにすること。** レポートは相対パスで図を参照している。

## 読み方 — まずサマリから

**出力は「集計」と「列挙」の 2 層になっている。**
コンテキスト長 4K トークン程度のローカル LLM でも扱えるようにするためである。

```
1. report_summary_{年月}.md          全体像。1 ファイル 4,000 バイト以内
        ↓ 「どのホストが荒れているか」が分かる
2. report_{ホスト名}_{年月}.md        の先頭「1. このホストの集計」   最大 674 バイト
        ↓
3. 個々のイベント本文とチャート        ここは大きい
```

### `report_summary_{年月}.md`(全ホスト横断の集計)

| 章 | 内容 | 上限 |
| --- | --- | --- |
| 1. 全体の集計 | 対象期間・ホスト数・イベント数・脅威度別の内訳 | — |
| 2. ホスト別の集計 | どのホストを見るべきか | 10 行 |
| 3. 日別のイベント数 | いつ荒れたか | 10 行 |
| 4. 複数ホストで同時に発生したアノマリー | 横断的な事象 | 8 行 |
| 5. 実行時の注意事項 | 読み飛ばした行・スキップした系列・失敗したアルゴリズム | — |

**すべての表に行数上限がある。** ホストが増えても期間が伸びても、このファイルは大きくならない。

### `report_{ホスト名}_{年月}.md`(イベント本文)

1 イベント = 1 ブロック。**10 項目を必ず持つ**(該当が無い場合も「(なし)」と書く)。

```
# イベントID( EVT-20260605-host01-015 )
* イベント種別 : 検知したアルゴリズム ID
* 脅威度       : SEVERE / FATAL / WARN / INFO
* データ       : テーブル / メトリクス / 系列を特定するキー
* 値           : 該当区間の値
* 開始 / 終了  : yyyy-mm-dd HH:MM:SS (タイムゾーン)
* 現象         : 何が起きたかの 1 行要約
* 説明         : なぜ異常と判断したか(使った統計量と閾値)
* 原因候補     : 9 つの原因ルールとの照合結果(確度つき)
* 同時に発生したアノマリー : 発生時間に重なりのある他のアノマリー(最大 10 件)

![...](charts/EVT-20260605-host01-015.svg)
```

## 見どころ

### 1. 上限への張り付きの検知

ホスト別レポートに、**Java ヒープ(Old 領域)が実際の上限の 90% 以上を
1 日以上にわたって占め続けた**という検知が出ている。

```
ALG-C1: 実際の上限 100 の 90% (90) 以上が 1.2 日続いた (期間中の平均 93.89, 最大 97.93, 335 点)
```

**「増え続けている」でも「一時的に跳ねた」でもない、「上限に達して頭打ち」という状態**を
捉えるためのアルゴリズムである。**上限に達すると増加が止まる**ため、
傾向を見る手法では原理的に取りこぼす。

### 2. チャート(SVG)

`charts/` の各図は **2 段構成**である。

| 段 | 内容 |
| --- | --- |
| 上 | そのイベントの系列を**実単位**で描き、異常と判定された区間を黄色で網掛け |
| 下 | **同時に発生したアノマリー**を重ねる。各系列を自身の最小〜最大で 0〜100% に正規化 |

**下段の縦軸は無次元である。** DB コネクション数・メモリ使用率・待ちジョブ数は
単位が違い、そのままでは同じ縦軸に載らない。実際の最小値・最大値は凡例に併記してある。

**SVG は外部ライブラリを使わず自前で生成している。** 図の文字は閲覧側のフォントで
描画されるため、日本語が確実に表示される。

`charts/no-chart.svg` は「チャートなし」を示す共通の画像で、**全体で 1 ファイル**である。
上限や脅威度で対象から外れたイベントは、これを参照している。

### 3. 同時に発生したアノマリー

```
* 同時に発生したアノマリー :
  - EVT-20260605-host01-015 (同一ホスト) jvm_gc / ou : FATAL / 重なり 5 分
  - EVT-20260605-host09-008 (他ホスト) db_connection / active_connections : FATAL / 重なり 5 分
```

**「DB コネクションの高止まりと利用メモリの高止まりが同時に起きている」**といった、
アノマリー同士の同時発生を見つけるための欄である。
**相手のイベント ID にホスト名が含まれる**ため、どのファイルを開けばよいかが行から分かる。

## 再生成の方法

**本体のリポジトリで**次を実行する。

```
S_ANOMALY_A006_KEEP=./docs/report-samples \
S_ANOMALY_RUN_A006=1 \
python -m unittest discover -s app/tests/acceptance -t app -p "test_a006_performance.py" -v
```

テストは一時ディレクトリで動くため、放っておくと生成物は消える。
`S_ANOMALY_A006_KEEP` を指定すると、片付けの前にここへ複写される。

**本体のリポジトリでは、このディレクトリの中身を `.gitignore` で除外している**
(100MB を超えるため)。**本サンプルは資料として別に公開している。**
